# Shared Content publishing

Admin → Content contains 524 imported source entries: 6 chyron messages, 270 challenges, 20 programs, 126 exercises/movement definitions, 50 avatar options, 10 themes, 6 recipe summaries, 5 member lesson summaries and 31 reward/rarity entries.

Import: scripts/import-content-banks.cjs is read-only by default. --apply inserts absent stable source identities and baseline releases in one transaction; existing drafts and publications are never overwritten. It reads the app catalogs and the website's public exercise library. Personal records, private member templates, staff Academy assessments and answer keys are deliberately excluded. Recipe and member lesson sources contain summaries, not completed long-form curricula; the importer does not invent missing instructions.

Storage: app_content_drafts is admin-only; app_content_publications exposes only released content; app_content_history retains publication snapshots. Admin writes enforce role, configured MFA and optimistic revision. Publishing saved drafts happens through /api/admin/content/publish and the database publish_app_content RPC. Invalid URLs and stale revisions are rejected. No browser grants currency or marks challenges complete.

Readers: /api/content exists in both repositories. It serves cached, ETagged bank pages with 40 catalog summaries, opening full fields only for the requested detail. Small banks (chyron, avatar, themes, challenges and rewards) are bounded to 400 entries per request. Shared client requests deduplicate in flight and retain a one-minute memory cache. Server and CDN caches use 60-second lifetimes; already-open pages do not poll and may require a revisit/reload. No draft or member data enters this public cache.

App integration: the header uses published quotes/trivia; challenge cards use published labels/targets with existing evidence rules; Avatar Lab reads item labels and shirt unlock costs; authored shirt print assets can be replaced for existing styles; avatar and calendar backgrounds read published assets; exercise detail cues fetch the requested release only when opened; prize amount previews read published amounts. /dashboard/content and /coach/library expose every released bank. Recipes and Learning also expose the shared library.

Website integration: Client Hub Resources exposes the same shared banks. Shared program listings now use summary pages and on-demand definitions instead of fetching all full programs on every render. Calendar theme readers overlay shared releases. These website source changes still require their normal deployment; no production release was performed in this task.

Program publication creates a NEW immutable review version and keeps existing enrollments pinned to their original version. Existing budget/reward validation remains active. Publication to the catalog does not falsely open unfinished programs for enrollment. Edit the complete Program JSON for schedule/signal/reward changes; descriptive fields alone are not executable activity definitions.

Future weekly coin, bolt and gem amounts are read by the existing server award function from published reward entries. Eligibility, rarity odds, gem selection, idempotency and past award amounts remain unchanged. Chest currency amounts and upcoming inventory fulfillment retain their existing rules. Cosmetic publication does not generate new mesh shapes, animations or an unimplemented shop checkout; existing compiled style identities remain required for Avatar Lab.

Usage evidence: import payload ~1.23 MB raw / 61 KB gzip (one-time authoring migration, not a page-load payload). Measured local API responses: 6 chyron entries 1,871 bytes; all 20 plan summaries 3,936 bytes; 40 exercise summaries 8,074 bytes. An unchanged summary request returned 304 with zero body bytes. Images/videos/GLB bytes are not copied into JSON. Actual total usage depends on visits and media sizes; provider quotas and account usage were not inspected.
