# App Map

Sound Fitness is a Next.js App Router app with member, admin, coach, onboarding, nutrition, stats, performance, learning, and soundworld areas.

## Stack

- Next.js `16.4.0`
- React `19.2.4`
- Tailwind CSS `4`
- Supabase auth/data client
- Stripe checkout/webhook integration
- Three.js and 3D dashboard UI components
- Lucide React icons

## Key Source Areas

- `app/`: route files, layouts, and page-level experiences
- `components/`: shared UI, marketing, auth, dashboard, onboarding, anatomy
- `components/dashboard/`: member dashboard shell, 3D assets, dashboard navigation and cards
- `components/dashboard/DashboardExperience.tsx`: shared dashboard implementation. `/dashboard` renders the full experience; `/dashboard/profile` uses `headerOnly` with its existing Profile content. Both render the same header menu and overlays; dashboard body scrolling/row mounting are disabled in header-only mode.
- `lib/routes.ts`: centralized route constants
- `lib/supabaseClient.ts`: Supabase browser client and user helper
- `lib/profile-storage.ts`: profile-related local/storage helpers
- `lib/training/`: normalized exercise catalog and movement intelligence
- `lib/exercise-system/`: exercise catalog, matching, progression, aliases, modifiers
- `lib/localData/`: local workout and builder data
- `lib/planning/`: account-scoped goals, weekly plans, completion logs, recommendations, calendar projections, and optimistic cloud sync. `PlanningProvider` initializes this store before the member profile/dashboard renders.
- `lib/planning/checkIns.ts`: account-scoped weekly feedback/history and recoverable per-week drafts with explicit ratings, stable weekly identity, stale-editor protection, and atomic completion/draft clearing. `/dashboard/progress/check-in` restores partial answers, retains older unfinished weeks for review, and saves through planning sync; coach messages and website 30-day check-ins remain separate actions.
- `lib/planning/journal.ts`: account-scoped journal entries and recoverable drafts, atomic entry/draft saves, stable retry identity, and stale-editor protection. Journal entries are not sent as coach messages.
- `lib/planning/painLogs.ts`: explicit account-scoped pain reports and recoverable partial drafts with rating/body area/notes, stable retries, atomic report/draft completion, validation, and account/conflict/stale-editor guards. Reports do not infer recovery or automatically change plans/send messages.
- `lib/planning/habits.ts`: actual named habits and daily Done/Not done/Not reported answers with stable retries, stale/account guards, local-date validation, archive/restore, and retained reported history. `/dashboard/progress/habit-tracker` replaces the unrelated training prototype and is linked from Progress.
- `lib/planning/hydration.ts`: actual dated water entries in ml/US fluid ounces, stable retries, stale/account guards, correction/removal, and local seven-day totals. Account drafts recover unfinished entries/corrections with captured entry revisions; final saves atomically clear matching drafts. `/nutrition/hydration` reads saved Goals water targets and explicit unreported days; history browsing is separate from the form. Nutrition initializes planning before profile data. The labeled Fuel Journey progress remains a preview.
- `lib/planning/meals.ts` and `mealValidation.ts`: actual meal entries and recoverable drafts, optional local times/types, manually reported energy/macros, canonical revisions, stable retries, atomic final-save/draft clearing, and correction/removal. Unknown nutrition stays null and explicit zero remains zero; totals report field coverage. `/nutrition/meals`, `/nutrition/meals/builder`, and `/nutrition/meals/history` share the real MealLog form/history/search/date filters. Meal-template reuse is implemented through `mealTemplates.ts`/`mealTemplateValidation.ts`: save a reported meal as a template, create/edit/archive templates, and start a protected dated draft without recording additional intake until Save meal. `/nutrition/meals/templates` owns these controls; the separate Recipes module remains a preview.
- `lib/planning/nutritionSummary.ts`, `usePlanningDay.ts`, and NutritionSummary: shared reported-only meal/water totals, unit conversion, saved protein/water targets, and seven local days of history. Fuel Dashboard, Macros, Calories, and Nutrition Progress use actual account records; no sample adherence, deficits, or AI intake advice. Current-day views refresh across midnight/focus/visibility changes while drafts retain their chosen dates. Fuel Journey and other remaining nutrition modules are labeled previews.
- `lib/planning/libraries.ts`: account-scoped Nutrition/Recovery/Mobility/Performance favorites, recent items, and draft selections. Adds and favorite projections commit atomically; explicit library imports preserve older browser originals. Dashboard favorite cards use the same account records. Mobility and Recovery retain their shared draft. Library selections are separate from actual intake logging in `/nutrition`.
- `lib/planning/progress.ts`: actual progress overview derived from logs, weekly assignments/goals, check-ins, and journal entries. `/dashboard/progress` has no sample strength gains, body-volume percentages, reward totals, or coach advice.
- `lib/planning/history.ts` and `components/dashboard/WorkoutHistoryView.tsx`: actual planning workout completions, exercise review, search/date filters, and local JSON export. Logger completion opens the saved session identity on `/dashboard/sessions/workout-complete`; absent records never fall back to sample sessions.
- `lib/planning/availableLogs.ts` and `cloudHistory.ts`: paginated, account-scoped cloud-only completion reads merged into History/Progress without writing another planning copy. Planning identities take precedence; loaded cloud assignments also protect plan/calendar edits. Refreshes run on load/focus/reconnect and manual retry, with explicit loading/unavailable coverage and same-account cached data status.
- `lib/planning/dashboardCalendar.ts` and `components/dashboard/useDashboardCalendarEntries.ts`: project canonical calendar/plan records into Dashboard Calendar and Training Constellation alongside account-scoped personal entries. Live calendars do not generate sample sessions.
- `lib/member-services.ts`: authenticated reads of shared website messages, booked sessions, and package balances; message writes use the staged member-message RPC.
- `lib/planning/bookings.ts`: account-checked, read-only website booking projection shared by dashboard/standalone calendars. Refreshes on account load, reconnect, focus, and manual refresh; booking changes stay in Sessions & booking/website management rather than local planning writes.
